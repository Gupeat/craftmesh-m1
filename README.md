# CraftMesh M1 · 工艺协同中台（参考实现）

一个可运行的 M1 纵向切片：把纹样授权、AI 共创、可制造性判定、报价与订单状态机串成同一条可追踪的请求链路。全部数据为合成/脱敏数据，不接真实客户、工厂或版权方。

## 环境要求

- Python 3.10+（只用标准库，无第三方依赖；本机使用 Python 3.12.14）
- 现代浏览器（Chrome / Edge / Firefox）
- 无需 Node、数据库服务或构建步骤；SQLite 文件由服务端自动创建

## 一条命令启动

    python server.py

默认监听 http://127.0.0.1:8787/ ，数据库为当前目录的 m1.db。也可以指定端口：

    python server.py --port 8788

打开首页后，右上角可以切换角色：设计师 / 评审 / 生产运营 / 质检 / 财务 / 管理员。角色决定订单上可见的可执行动作。

## 四条可点流程

1. 工作台：选纹样、工艺、材料与 12 个工艺参数，点“运行可制造性检查”，查看逐条规则证据、授权快照与报价。
2. 工作台：点“创建订单草稿”生成订单；右侧订单列表实时出现。
3. 订单中心：打开订单详情，按角色执行状态迁移；退回修改/质检退回必须填写备注，越权与非法迁移会被服务端拒绝。
4. 规则与授权 / 架构与验收 / 测试证据：查看 10 条规则、3 条硬约束、授权台账、A01–A10 对照与真实测试报告。

## 规则与边界

10 条规则，3 条硬约束：CAST-WALL（铸件最小壁厚）、INLAY-GAP（镶嵌最小间隙）、CARVE-GRAIN（逆纹雕刻限制）。硬约束失败会阻断创建订单；软约束失败返回“需复核”。授权校验是显式的，来源、使用范围、授权编号、二创许可逐项校验，并且快照随单固化。

M1 不包含：真实工厂排产、支付通道、C2M 预售/退款争议、多语言站点、文化 IP 短视频管线。这些属于 M2–M4，不在本页虚标。

## 测试与验证

运行全部测试：

    python -m unittest discover -s tests -v

当前结果：27/27 通过（19 个核心单测 + 8 个 HTTP API 集成测试），约 1.07 秒。详细记录见 TEST-REPORT.md。

浏览器验证：Edge headless 渲染首页、订单中心、订单详情、规则、架构、测试六个入口，检查了 API 在线、订单详情、A01–A10 与测试证据的可见文本。

## 生成演示订单

服务启动后，在另一个终端执行：

    python seed_demo.py --base http://127.0.0.1:8787

脚本通过公开 HTTP API 创建 3 张合成订单（待评审 / 质检中 / 已结算），用于演示 KPI 与状态机。已有订单时默认跳过；加 --force 可追加。

重置演示数据：右上角切换到“管理员”，点“重置数据”（或 POST /api/demo/reset，body 为 {"role":"admin"}）。

## HTTP API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/health | 服务与订单数 |
| GET | /api/bootstrap | 纹样、规则、参数、角色、状态机定义、订单与统计 |
| GET | /api/orders | 订单列表 |
| GET | /api/orders/{id} | 订单详情（含审计轨迹） |
| POST | /api/check | 可制造性判定、授权校验与报价 |
| POST | /api/orders | 创建订单草稿（硬约束/授权失败返回 422） |
| POST | /api/orders/{id}/transition | 角色化状态迁移；越权 403、非法迁移 409、缺备注 422 |
| POST | /api/demo/reset | 管理员重置演示数据 |

静态资源只允许首页、样式、脚本、README、测试报告和三张截图；`m1.db`、服务端源码与测试源码一律返回 404。

## 文件

    server.py         HTTP 服务、路由、静态文件白名单
    core.py           纹样、10 条规则、授权校验、报价、状态机
    store.py          SQLite 订单与审计持久化
    index.html        前端页面
    styles.css        样式
    app.js            前端逻辑
    seed_demo.py      合成订单种子脚本
    tests/            unittest 核心与 API 测试
    TEST-REPORT.md    最近一次实测记录

## 真实项目接入时

把合成纹样替换为获授权或脱敏的纹样库，补齐 factory adapter、支付/退款与合同状态、真实权限体系与审计留存策略，再按 M2–M4 逐步接入。演示中的“通过”只是规则初判，正式制造仍需工艺师复核。
